# CLAUDE.md — argus-mint

Guidance for AI agents working in this repo. Human-facing usage lives in [README.md](README.md); this file is the orientation an agent needs to change code safely.

## What this is

Provenance tokens for game assets. A Python package (and an HTTP service, `argus-mint serve`) plus Foundry contracts that render art from **reviewed templates** through darklight, pin it to IPFS, build canonical ERC-721 metadata, mint transferable **Card**s and soulbound **Deed**s, and anchor commit/reveal secrets and Merkle roots in a **Ledger** contract so anyone can verify a consumer's records. First consumer: atlas-realms (a browser strategy game; repo smk762/argus-realms, package `atlas_realms`), which writes its own adapter.

**argus-mint has no game in it.** It never knows about units, battles, hexes or coins. A consumer supplies a template's variables, a record to show, and 32-byte leaf hashes. Out of scope: game rules/stats, marketplaces, fungible tokens, staking or yield, free-text prompts, a frontend (only a JS verifier module ships; the UIs are argus-studio's pages and argus-assay, clients of `argus-mint serve`).

## Hard rules (a change that breaks one is a bug)

1. **No raw prompts.** A render is a template id + variables, each picked from that template's fixed list. Free text (the card name, consumer display text) may appear in metadata and on the card image, never in a model request, image or text. `templates.fill` rejects values outside the list, missing or extra keys. The bio writer sees only the variables and a literal `{name}` token; the name goes in afterwards (`bios.write_bio`).
2. **Only reviewed templates, frames and bio templates make cards.** Status `draft | approved | retired`; only `approved` templates render cards, only `approved` frames go on them, and only `approved` bio templates write their bios. Approval is a human step recorded in the file (`approved_by`, `approved_at`). `argus-mint sample` / `render.render_for_review` render drafts for their reviewer, to local files only: never pinned, signed or minted.
3. **Retry, don't loosen.** A safety rejection is retried with a new deterministic seed up to `max_attempts`. Never change the prompt or disable the check. Every attempt's seed + outcome is recorded.
4. **Tokens carry no power.** Metadata describes a record; it never holds a number a game reads back as a stat. Card text (class, stats) is display text the consumer supplies, drawn on the image only; the bio writer is told to write no numbers or stats, and a reply with a digit is retried. Contracts have no hooks a game calls to decide outcomes.
5. **Nothing pays out.** No fungible token, revenue share or staking. Royalties, if any, are standard ERC-2981 on resale.
6. **Consumers' deterministic code never reads the chain.** The indexer copies chain state into the consumer's DB; game logic reads that copy.
7. **Reproducible.** Same template version + variables + seed → same render request. Metadata JSON is canonical (sorted keys, compact separators, UTF-8) so its hash is stable.
8. **Pure core.** `templates`, `metadata`, `merkle`, `vouchers`, `siwe` are pure (no I/O beyond reading a template file) and tested without a network. Network code (darklight, IPFS, RPC) lives in thin, injectable clients behind `Protocol`s.
9. **Every card image is reviewed before it is published.** (With `ARGUS_MINT_AUTO_MODERATE=1` the platform's checks may stand in for the moderator; the owner always reviews.) `draft` (render + frame, local files) → `review` (the moderator **and** the owner each approve or reject the exact image, bound to its sha256) → `publish` (pin, metadata, signed voucher). `cards.check_publishable` refuses anything else; a rejection closes the draft. Nothing reaches IPFS or a voucher before both approvals.

## Settled decisions (beyond the spec)

- The ERC-721 contract is **`Card`** (not `UnitCard`): no game words in argus-mint. EIP-712 domain name `"argus-mint Card"`, version `"1"`. Token name/symbol are constructor args.
- The voucher's **`contentHash` = keccak256(canonical({"image": …, "provenance": …}))** — only the immutable part of the metadata, so it stays checkable after live attribute refreshes. `metadata.content_hash()` is the one place this is computed, for cards and teasers alike. A teaser's provenance is `metadata.TeaserProvenance` (`kind: "teaser"`, its record by file), and its asset id is `keccak256(utf8("argus-mint/teaser/<project>/<T n>"))` (`metadata.teaser_asset_id`), so a teaser mints once; a card's provenance has no `kind` and is unchanged. Provenance records the render's choices (`variables`, `model`, `loras`; `Provenance.for_render(req, …)` is the one builder) so the request can be rebuilt from public metadata; unset fields are left out, so cards minted without them (before 0.2.1) hash as before.
- Template hash = keccak256 of the canonical JSON of the template **minus `status`**, so retiring a template doesn't change the hash cards already carry. `approved_by`/`approved_at` are included.
- Ledger commitments are **sha256** (atlas-realms already publishes `sha256(secret)`); Merkle leaves are OpenZeppelin `StandardMerkleTree` `["bytes32"]` (double keccak).
- **Target chain: Base** (OP Stack; mainnet 8453, testnet Base Sepolia 84532), chosen 2026-11-08 for consumer onboarding and ecosystem exposure. `networks.py` holds the constants; `foundry.toml` has `base` / `base_sepolia` RPC and Basescan entries; `make deploy [NETWORK=base]` deploys and verifies (settings in `.env`, deployer from a Foundry keystore, never a raw key in a file).
- Indexing on Base: follow `Web3Rpc(w3, head="safe")` with `confirmations=0` rather than counting blocks on the sequencer's unsafe head (`safe` trails `latest` by about 2 minutes on mainnet.base.org).
- **No explorer API is needed to run anything**: deploy, mint, reads and indexing are plain JSON-RPC. `networks.*.public_rpcs` lists keyless endpoints (checked 2026-11-08) and `chain.connect()` fails over between them, skipping any on the wrong chain id. Public endpoints cap `eth_getLogs` ranges, so use `max_blocks≈500` on them. Contract verification defaults to Sourcify (free); `VERIFIER=blockscout|etherscan` are the alternatives, and only etherscan needs a key.
- Contracts are not upgradeable; a new version is a new deployment.
- **OpenZeppelin is pinned to v5.4.0 and `evm_version = "cancun"`** on purpose: OZ ≥ 5.5 emits the `clz` opcode, which needs Osaka. Base's Osaka support was unconfirmed when chosen; bump both together only after verifying it (e.g. deploy a CLZ probe to Base Sepolia).
- `Deed`: each `recordId` mints once, ever (a burned deed's record stays used), so a retried mint can't duplicate. The consumer makes per-player records with e.g. `keccak256(feat, player)`.
- `Ledger.reveal` works once per epoch and is open to anyone; `Card.refresh`/`freeze` revert after freeze; `setBaseURI` emits `BatchMetadataUpdate` over all minted ids.

## Layout

`src/argus_mint/`: the pure core (above), then thin clients behind `Protocol`s (`render`, `pin`, `indexer`, `darkroom`, `bios`), web3 clients (`chain`, `ledger`; the `chain` extra), and `workflow` (`create_draft`/`publish`, shared by `cli` and `server`). Teaser projects: `projects` and `spoilers` (pure), served by `server_projects`; `references` checks identity references with argus-cortex (not pure: cortex's import loads its HTTP clients); `backgrounds` (scene renders and their review, stored under `ARGUS_MINT_BACKGROUNDS_DIR`) and `teasers` (inpaint, frame, bake a teaser draft), served by `server_teasers`; `posting` (posts, anchors of posted teasers, the export), served by `server_posts` and the CLI's `teasers anchor` and `export`; `training` (an identity's LoRA: candidates, curator, lens, forge, proof, pin; records under `ARGUS_MINT_TRAINING_DIR`) with its HTTP clients in `training_clients`, served by `server_training`; `identity_check` (proof's score of a teaser's figure, recorded in `auto_check.identity` by `moderation`; `POST /drafts/{id}/identity-check` in `server_teasers`); `projects/example-teasers` is a neutral example, and real projects live outside the repo (`ARGUS_MINT_PROJECTS_DIR`). A project's own frames are in `<project>/frames/`, ids `<project>/<name>` (`frames.frame_scope`: where the file lives decides), merged into the server's frame table and its routes (the `frame_id` URL convertor takes the two-part id; versions are `int` so the parse is unique); `scripts/capture_frame.py` builds an overlay from local HTML with Playwright (not a dependency; the example `projects/example-teasers/frames/harbour-feed-v1` is captured with it from `frames/src/harbour-feed/`). `abi/` holds committed ABIs so pip users never need Foundry. `contracts/` is Foundry (OZ and forge-std as submodules); `verifier/` is the JS verifier; `templates/`, `frames/`, `bios/` hold example catalogue files (`frames/example-teaser-v1` is the full-bleed teaser frame, drawn by `scripts/make_teaser_frame.py`); `docs/` is served by argus-assay at /docs. Generated and committed: `docs/cli.md` (`make cli-docs`), `schema/mint-wire.schema.json` (`make schema`), `fixtures/api/` (`scripts/api_fixture.py`, the UIs' demo mode), `tests/fixtures/`.

Extras: base install = pure Python (no web3); `chain` = web3; `cli` = Typer; `frames` = Pillow; `server` = FastAPI + uvicorn + argus-cortex[server,remote] (implies cli, frames); `dev` = tests.

## Facts the code doesn't show

**darkroom** (argus-darkroom, `:8106`, is darklight)
- It serves one generation at a time; a 409 is waited out (`busy_wait`, `busy_timeout`). Server-to-server calls send no `Origin`, which its write guard allows.
- Outcomes: `passed` ok; `review` is a safety rejection unless `accept_review`; `deleted`/`omitted` safety rejections (retried); `refused` an error, because pre-flight judged the template text and another seed can't help; `failed` an error. Only safety rejections are retried (`derive_seed(seed, n)`); transport retries belong inside the client.
- `final_prompt` must match darkroom's `assemble_prompt` (prompt, then trigger words not already present).
- Workflows: darkroom ≥ 0.1.3 picks one per checkpoint family and LoRA count; LoRAs need a workflow with `$lora` slots, and older darkroom refuses (400) any request with LoRAs. Flux workflows have no `$negative` slot: Flux's negative must be `""`, and darkroom refuses a negative, `guidance` or `clip_skip > 2` a workflow can't take. `darkroom.check_template` finds all of this before approval; the server refuses (409) approving a template with problems when a darkroom is configured.
- The template's `width`/`height` go inside `sampling`; match the render's aspect to the frame's art window, because the compositor crops to cover.
- Inpainting (teasers): `init_image` with `mask_base64` (white repaints). darkroom picks `<family>+lora<N>+inpaint.json` and refuses (400) a mask with none: its examples are SDXL with 0 or 1 LoRA, so an identity LoRA plus the style LoRA needs a `sdxl+lora2+inpaint.json` there. `/models` lists `inpaint_lora_counts` per checkpoint; `darkroom.check_inpaint` reads it before a teaser renders, and `darkroom.check_render` reads `lora_counts` before a background job (backgrounds take the project's `style_lora`). The record names the input and mask by `source_sha256`, which the client checks.
- Renders: darkroom leases the GPU itself; mint sends only `X-Argus-Priority`. mint leases the GPU only for the bio writer (`gpu.py`; its figures equal `gpu-tenant.yaml`, a test keeps them so).

**Identity training** (`training.py`; docs/projects.md#training-an-identity)
- curator: no token, writes refused by `Origin` only. Its `face_source` filter is HTTP-reachable on `/scan/{id}/select`, but `/select` returns rows in scan order (mint ranks by the scan's face distances), and it has no train/held-out split and no consistency measure without a face. `require_adult` needs `faces.mivolo`.
- lens: `/caption/folder` and its sidecars hold the `identity` caption (`target_category` can't name `training`), so mint uses `/caption/batch` and writes `<stem>.txt` itself.
- forge: `/run` only runs a config `/config` wrote (`dry_run: false`); with training off (`ARGUS_FORGE_READONLY`, the default) `/config` silently previews and `/run` is 403. No route returns the LoRA: it is `<export>/forge/kohya/output/<output_name>.safetensors`. Runs live in memory (a restart forgets them). It trains every image under the export dir, so references live in a separate export.
- proof: no `POST /run`, only `/run/stream`; no job route (mint passes its own `run_id` and reads `/report/{run}`). References are `<export>/references/` of an export under `ARGUS_PROOF_EXPORTS_DIR`. Scorers and gate can't be chosen per run, and `likeness` has weight 0 in its verdict.
- proof's `POST /score` (the teaser identity check, `identity_check.py`): multipart `images` (1–16) plus a `request` part, a `ScoreRequest` as JSON (`export`, `scorers`, `target_category`, `crops`); stores nothing, takes no token. A crop is in the uploaded image's pixels after its EXIF orientation, so mint sends art at the scene's size with none. 503 means a scorer can't run or the GPU lease was refused (mint: `unavailable`, held); 400/404/422 are refusals (`error`, held). `identity` (ArcFace) reads `None` without a face, or for a `target_category` other than `identity`. Its `/health.capabilities` lists `score` unless proof is read-only.

**Hash stability.** Fields added to provenance or templates (`variables`, `model`, `loras`, `frame`, `art`, `style`, `bio`, `models`, `guidance`, sampling overrides) are left out while unset, so cards minted before them hash as before. Keep it that way for any new field. A project file's frame link (`projects.FrameLink`, which also takes `<project>/<name>`) dumps exactly as a `Ref`, so project files hash as before. Approving a draft template changes its hash, so a library entry is checked against the approved template with the hash set aside.

**Bios** aren't reproducible (no seed). The text is kept in the draft, drawn on the card and used as the metadata `description`; provenance records `bio` {id, version, hash, model}. The text guard screens the reply with the `{name}` token still in.

**The service** (`argus-mint serve`, port 8108; argus-assay is on 3108)
- The moderator (bearer `MODERATOR_TOKEN`) creates, reviews and publishes. The owner reviews and edits by SIWE only; the moderator never edits. A SIWE nonce lives in memory, is single use and expires in 10 minutes, so a restart voids open challenges. An edit's challenge covers the sha256 of the canonical edit.
- An edit redraws a framed draft with the exact frame it was made with (by hash) and needs both approvals again. `frames.tint_matrix` is the one definition of the tint: the browser applies the same numbers in an sRGB `feColorMatrix`.
- Catalogue approval through the API rewrites the YAML (the served directories must be writable) and leaves a file change to commit.
- Reviews, `auto_check` and `made_with` stay in `draft.json`, never in public metadata or provenance. A teaser's `auto_check` is recorded with auto-moderation off too (its identity check must be on record); `passed` is then always false, so `passed` still means an approval was recorded. Library thumbnails are previews only, never a card's image.
- Samples are jobs on one background thread, never pinned; a job a restart left queued or running reads as failed. Background jobs (`server_teasers.BackgroundRunner`) work the same way, at `batch` priority.
- A teaser draft is a `CardDraft` with `kind: "teaser"`: no `asset_id`, `consumer` or bio, plus a `teaser` record. A card draft written before `kind` loads as `kind: "card"`. Its PNG is baked with critical chunks only (`teasers.bake_png`), so a poster's metadata-stripped copy hashes as the reviewed one.
- Posting and publishing are each optional after both approvals. argus-herald (the poster token, `ARGUS_MINT_POSTER_TOKEN`, accepted only by `POST /drafts/{id}/posted`) polls `GET /posts/ready` and reports posts back; mint never pushes. Posts live beside the draft in `posts.json` (like `publish.json`), never in `draft.json`, so a card's draft file is unchanged. `teasers anchor` and `export` read the server's drafts directory, and keep anchors and trees under `ARGUS_MINT_ANCHORS_DIR` (per project, outside the repo); the tree is written before the transaction, the record after it lands.

**Chain and IPFS**
- `LocalPinner` CIDs equal IPFS's only for single-chunk (≤ 256 KiB) files. A Kubo `add` of a larger file returns a dag-pb CID (`bafybei…`); that's expected.
- `submit`/`freeze`/`anchor` pre-check what the contract would refuse before asking for a password or spending gas. `anchor --tree` writes the dump *before* sending, so a landed root always has its tree.
- The CLI logs to stderr; every result is JSON on stdout.

## Commands

`make help` lists the targets. `make check` (lint, test, forge-test, verifier-test) must be green at the end of every milestone. After a change, regenerate and commit what it touches: `make cli-docs` (CLI), `make abi` (contracts), `make schema` (wire), `make lock` (dependencies). Foundry lives in `~/.foundry/bin` (the Makefile finds it there); Node in `~/.local/bin`.

## Conventions & gotchas

- **Versioning is git-tag-derived** (`hatch-vcs`); `_version.py` is generated. Each milestone ends with a pre-release tag (`v0.0.1a1`, `v0.1.0a1`, …) and a CHANGELOG heading. Headings are Keep a Changelog style (`## [Unreleased]`, `## [0.2.1] - 2026-11-14`): the release workflow takes the tag's section as the GitHub Release notes and fails before publishing anything if the tag has no section (pre-releases included). The Release is created last, once PyPI has the version, with the wheel and sdist attached.
- **ABIs are committed and checked in CI** — after a contract change run `make abi` and commit the result in the same commit.
- **Fixtures:** `tests/fixtures/merkle.json` comes from the reference JS library (`@openzeppelin/merkle-tree`) and must never be regenerated to make a failing test pass. `vouchers.json` and `proofs.json` are Python-built (`scripts/py_fixtures.py`) for the forge tests; `tests/test_fixtures.py` fails if they're stale.
- **Forge gotcha:** `sha256(...)` / `ecrecover` are precompile *calls*, so they consume a pending `vm.prank` / `vm.expectRevert`. Compute hashes before the cheatcode.
- Tests marked `anvil` start a local node and deploy from `contracts/out`; they skip without Foundry unless `ARGUS_MINT_REQUIRE_ANVIL=1` (CI's contracts job sets it).
- `uv.lock` is committed; a dependency change needs `make lock` in the same commit, and the same pins in `requirements-test.txt` (the plain-pip test environment ai-code-auditor's `validate_patch` uses; `tests/test_requirements_test.py` checks it).
- Template origin: `argus-pkg-template` via copier. The Dockerfile and GHCR image job are back (for `argus-mint serve`), adapted: the image's context has no `.git`, so the release job passes `VERSION` as a build arg (`SETUPTOOLS_SCM_PRETEND_VERSION`). A `cortex-released` dispatch from argus-cortex's release rebuilds the newest final release's image (no cache), so a new argus-cortex inside the `server` extra's range reaches the service without a mint release; one outside the range needs that range raised and a release. CI is standalone because the shared argus-ci workflow has no Foundry hook.
- **Wire schema:** a change to `wire.py` (or a model it embeds: `Template`, `Frame`, `BioTemplate`, `CardDraft`) changes `schema/mint-wire.schema.json`; run `make schema` and commit it. Bump `WIRE_VERSION`'s major for breaking changes. Regenerate `fixtures/api/` when responses change shape.

## Branches

`dev` is the default branch and the base for every PR. Cut feature branches from `origin/dev` and bring them up to date by merging `origin/dev`, never `main`. Never open a PR against `main` or push work to it directly: `main` must never be ahead of `dev`. A release fast-forwards `main` to a `dev` commit that passed CI (`git push origin origin/dev:main`), then tags it. If `main` is protected and needs a PR, merge the release PR, then immediately merge `main` back into `dev` so the merge commit is not left on `main` alone.
