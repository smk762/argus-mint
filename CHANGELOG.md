# Changelog

All notable changes to this project are documented here. Versions come from git tags (`hatch-vcs`).

## [Unreleased]

### Changed

- **`GET /health` is also argus-cortex's `ServiceHealth` (wire 1.18, smk762/argus-cortex#212).** It is served by `install_health`, and every field it had keeps its name and value: `service`, `version`, `wire_version`, `read_only`, `network`, `chain_id`, `card`, `consumer`, `reviewers`, `siwe_domain`, `backends`, and `capabilities` as the same object of booleans (cortex 0.16.1 accepts that form). New beside them, and optional on `wire.Health`: `service_version`, `status`, `started_at`, `wire` (`{"wire_version": ...}`), `checks`, `build`, `peer`. The route still answers 200. `status` is `degraded` when a backend this server was given (darkroom, the writer, IPFS) doesn't answer, each reported in `checks` and cached for 10 s; a backend that isn't configured has no check. `GET /health?checks=0` skips the checks. **Behaviour changes:** the response carries `Cache-Control: no-store`; the route is no longer in `/openapi.json` (the wire schema is where `Health` is defined); darkroom is probed at `/health?checks=0`; and the three backend probes run at once instead of one after another.
- **argus-cortex 0.15 → 0.16**, pinned `>=0.16.1,<0.17` (smk762/argus-cortex#212, #209). Cortex now reads the GPU broker's URL and token through its suite file (`~/.config/argus/suite.env`, or `/etc/argus/suite.env` in a container) when the environment doesn't set them; with no suite file nothing changes. `ARGUS_GPU_COORDINATOR=none` keeps a host off a suite-wide broker.
- **Peer URLs fall back to the suite-wide name** (`argus_cortex.peers`). `argus-mint serve` reads `ARGUS_MINT_DARKROOM_URL`, `ARGUS_MINT_CURATOR_URL`, `ARGUS_MINT_LENS_URL`, `ARGUS_MINT_FORGE_URL` and `ARGUS_MINT_PROOF_URL` first, as before, then `ARGUS_DARKROOM_URL`, `ARGUS_CURATOR_URL`, `ARGUS_LENS_URL`, `ARGUS_FORGE_URL` and `ARGUS_PROOF_URL`, each from the environment and then the suite file. The CLI's `--darkroom` does the same. `off` leaves a peer unconfigured whatever the suite says. **Behaviour changes:** a value that is not an absolute `http(s)` URL now stops startup (`PeerRefused`, naming the variable and never the value) instead of failing on the first call; a trailing slash is dropped; and a host that sets a suite-wide name gets the capability it configures (`ARGUS_PROOF_URL` turns on `capabilities.identity_check`). `ARGUS_MINT_URL` is still only where others find mint. Compose's darkroom default takes `ARGUS_DARKROOM_URL` from `.env` before the host's `:8106`.
- **Compose labels the `mint` container for discovery**: `argus.peer: mint`, `argus.service: argus-mint`, `argus.health: /health`, `argus.port: "8108"`. The suite file is mounted by the opt-in `compose.suite.yaml` (`COMPOSE_FILE=compose.yaml:compose.suite.yaml`; compose can't skip a missing file, and the image runs as root, so today the mounted file must be root-owned, smk762/argus-cortex#218), and `.env.example` drops `ARGUS_GPU_BROKER_FALLBACK` (compose still defaults it to `none`; docs/deploy.md keeps it).
- **argus-cortex 0.14 → 0.15**, pinned `>=0.15,<0.16`. `ARGUS_GPU_BROKER_URL` (and `ARGUS_GPU_BROKER_TOKEN`) is all the GPU broker needs: cortex selects the broker from the URL alone and finds `gpu-tenant.yaml` in the working directory or at `/app/gpu-tenant.yaml`, where the image ships it. Compose no longer defaults `ARGUS_GPU_COORDINATOR` to `none` or sets `ARGUS_GPU_TENANT_MANIFEST`, the image drops its `ARGUS_GPU_TENANT_MANIFEST`, and `.env.example` and docs/deploy.md list the URL and token only. **Behaviour change:** a host whose `.env` sets `ARGUS_GPU_BROKER_URL` without `ARGUS_GPU_COORDINATOR` now leases bios from the broker; set `ARGUS_GPU_COORDINATOR=none` to keep the old behaviour.

### Added

- **`argus-mint serve` registers with the GPU broker at startup** (`gpu.keep_registered`, in the app's lifespan, with the bio writer's coordinator), re-registers every five minutes and signs off at shutdown, so argus-iris knows the tenant before its first bio. Nothing without a writer or a broker URL; a down broker never blocks startup. The CLI still registers with its first lease.

## [0.3.1] - 2026-11-23

### Changed

- **The server's project, scene, identity and sample job id checks use argus-cortex's `fs.safe_name`** (ai-code-auditor#60), with mint's own patterns in place of its default, so each is exactly as strict as before. `server_projects.is_id` replaces the copies of the id regex in `server_projects`, `server_teasers` and `server_training`. The base-install modules (`cards`, `library`, `training`, `backgrounds`, `posting`) keep their local checks.
- **The `train` step takes the LoRA forge reports (smk762/argus-forge#52).** forge now puts a succeeded run's LoRA on `GET /run/{id}` (`lora`: `export_path`, `sha256`), read from the config the trainer ran. mint uses that file instead of assuming kohya's layout, and refuses the step when forge reports no LoRA or the file mint sees hashes differently from forge's. A forge without the field (no `lora` key) is handled as before. With training disabled, forge now answers a writing `/config` with 403; the warning check stays for older forges.
- **argus-cortex `>=0.14,<0.15` is a base dependency** (it was only in the `server` extra, at `>=0.9,<0.10`; the server extra moves to the same range). Digests go through `argus_cortex.hashing.sha256_hex`, the same bytes as the local helpers, so nothing stored changes. `cards.sha256_hex`, `projects.text_sha256` and `capture_frame`'s own sha256 helper are gone. The requirements-test name check uses `packaging.utils.canonicalize_name`.

### Fixed

- **Auto-moderation off holds a card's check too.** `auto_check` with approval off records the hold for a card as it already did for a teaser, so `passed` is false. An identity check holds unless the outcome is `passed` or `uncalibrated` (a viewpoint's `skipped` stays clear); an outcome added later holds by default. The word filter loads when the server starts, whatever auto-moderation is set to, and a missing or unreadable list stops startup. A spoiler rule is matched against each text on its own.
- **An approved `project.yaml` can't be replaced.** Saving another version over a reviewed one is 409. Approving a file re-checks it under the lock, and anchor writes are locked. Malformed posting, consent and darkroom error inputs raise errors.
- **Training resumes only a run that still matches.** A resumed forge run or a reused proof report is used only when it matches the current config and LoRA sha256. Held-out references are checked against their sha256 before export. Run ids are escaped in URLs, and only finite scores count. An image ranked twice counts once in the train/held-out split. The copied LoRA is hashed before it replaces the published file, so a bad copy leaves the published one in place.
- **`capture_frame` resolves a path before it accepts it**, so a raw `..` path is refused. It always writes `status: draft` and the new overlay name, strips colour profiles and keeps file modes. A background id can't point outside its set. Chromatic aberration's shift is clamped to the image. Whole floats from 2^53 serialise the way JavaScript writes them, so a content hash still matches a JS verifier.
- **The example lamp-room figure box gives the keeper's head room.** `character_area` is `{x: 128, y: 256, width: 272, height: 768}`: left of centre, to the bottom edge, clear of the sill lamp and the wall picture, and tall enough for the head. The scene is a draft, edited in place, and its background seeds are unchanged.

## [0.3.0] - 2026-11-19

### Added

- **Frame effects (wire 1.17, #63, epic #47).** A frame may list `effects`, applied in order in `frames.compose` to the art once it covers the window, inside the window only, before the overlay and text: `barrel` (`strength`), `scanlines` (`spacing`, `thickness`, `opacity`), `noise` (`amount`, `monochrome`), `chromatic_aberration` (`shift`) and `vignette` (`strength`, `start`), each with every parameter required and bounded, at most eight (`frame_effects.py`). They are part of the frame's YAML, so reviewed with it and in its hash; an empty list is left out of the hash, so every frame without effects keeps its hash. Pillow only (no numpy; the `frames` extra is unchanged). Byte-stable: the noise is SHAKE-256 of a fixed tag, the art's sha256 and the effect's place, so the same art and frame give the same PNG in any compose (draft, edit redraw, preview, teaser bake), and the tests pin each effect's output. The browser's SVG preview can't draw effects; argus-assay should say "effects not previewed: the baked PNG is what's reviewed" for a frame with any. The example harbour-camera frame has mild ones. [docs/catalogue.md](docs/catalogue.md#effects).
- **The spoiler list reads a project's frames.** `GET /projects/{id}` scans each of the project's own frame files as raw text (every string and every comment) and reports hits by rule number in `checks.spoiler_rules`; approving such a frame through `POST /frames/{id}/{version}/review` is refused (409, `held by spoiler rule N`). Text drawn into an overlay PNG can't be scanned: the frame review docs say the reviewer checks the overlay by eye.
- **A project's own frames, and building an overlay from HTML (wire 1.16, #62, epic #47).** A teaser project may keep reviewed frames in `<project>/frames/`, named `<project>/<name>` (`example-teasers/harbour-feed`): the id is in the YAML, so it is in the hash, and a global frame's id has no `/`, so the two never collide. Where a file lives decides its scope (`frames.frame_scope`): `load_frame` refuses a scoped id outside its project's `frames/` and an unscoped (or another project's) id inside it. The server merges them into its frame table, so they are listed (`GET /frames`, with the new `FrameInfo.project`, and `file` relative to the projects directory), served, previewed, laid out and reviewed through the frame routes, which take the two-part id with the `/` plain or encoded (a `frame_id` URL convertor; the version in those routes is now digits only, so the id parses one way). `project.yaml`'s `frames`, a viewpoint identity's `frame` and the teaser links take them (`projects.FrameLink`, which dumps as a `Ref`, so project files hash as before); the checks report a frame of another project; a teaser draft pins the frame by hash as before, and a card draft refuses a project's frame (422). Global frames and their hashes are unchanged. **`scripts/capture_frame.py`** renders a local HTML page to a transparent PNG with Playwright's Chromium (every non-`file://` request refused) and writes or updates a draft frame YAML from a JSON spec (window, text slots), recording in comments, so no hash moves, the rebuild command, the sha256 of the HTML and of every local file it loaded, the vendored kit's name and commit, and the Playwright and Chromium versions; it never overwrites an approved or retired frame and validates before replacing anything. Playwright isn't a dependency (the tests use a stub renderer). Example: `example-teasers/harbour-feed` v1, a harbour-camera overlay made of its own CSS, full bleed, now the `lamp` identity's frame and T2's. How to vendor a kit such as monohud at a pinned commit: [docs/catalogue.md](docs/catalogue.md#building-an-overlay-from-html). The API fixture's server now has an empty projects directory, so it is the card demo wherever it runs.
- **The identity check on each teaser (wire 1.15, #51, epic #47).** After a teaser of an embodied identity is composed, argus-proof's `POST /score` scores its unframed art (`art.png`), cropped to the scene's `character_area` (the art's own pixels: mint refuses art of another size or with an EXIF orientation, and checks proof's echo of the crop), against the identity's `proof_export` on its `check_metric` (`identity_check.py`). The result is recorded in the draft's `auto_check.identity` (`IdentityCheck`): `outcome` (`passed`, `below`, `uncalibrated`, `skipped`, `unavailable`, `error`), the reason in words, metric, score, `min_score`, export, crop, and proof's provenance (`proof_version`, the scorer's name, version and pinned `model_file`). Under `min_score`, with no references to score against (an embodied identity with no `proof_export`), or with proof unreachable, answering 503 or refusing, the draft is held with the reason; an uncalibrated score (no `min_score` yet) is recorded and not held on, but can't stand in for the moderator. A viewpoint identity is skipped, saying why. A teaser's `auto_check` is now recorded whether auto-moderation is on or not; with it off, `passed` is false and `held` says so, and only with it on, and every check passed, is the moderator's approval recorded. `POST /drafts/{id}/identity-check` (moderator) runs a pending teaser's check again, against the files it was made from. `ProofClient.score` and `TrainingClientError.status` in `training_clients.py`; new capability `identity_check` (proof configured, not read-only). [docs/projects.md](docs/projects.md#the-identity-check).
- **Identity references carry an argus-cortex `Provenance`, and a real person's needs consent (#48).** `Reference.provenance` is cortex `Provenance` JSON (replacing the `generated`/`licensed`/`personal` label and `consent` id), checked server-side by `references.py` with cortex's models: only cleared kinds (`stock`, `synthetic`, `consented`) are approved, and a `consented` one needs its `ConsentRecord` in the private `ARGUS_MINT_CONSENT_DIR` (`<release_sha256>.json`), matching the provenance (`consent_matches`), binding the image's sha256, and covering `training` of the face today (`consent_valid`). Problems appear in `checks.problems` and block approving the identity; they never name the subject. Training checks again whenever it uses the references (the `select` and `evaluate` steps), so a consent revoked after approval stops it. `projects.py` stays pure.
- **Training an identity's LoRA (wire 1.14, #50, epic #47).** For an approved embodied identity with a reviewed `training` block, the moderator runs six steps one at a time, `POST /projects/{id}/identities/{identity}/{version}/training/{step}`: `candidates` (darkroom renders of the identity's prompt on one checkpoint, no LoRA, `batch` priority, derived seeds, safety rejections retried and recorded), `select` (argus-curator uploads and scans them with faces on, `face_source` keeps one adult identity, mint ranks and splits the closest into `train` images and `held_out` references, curator exports both by `selection`; a sha256 check refuses a reference that is a training image), `caption` (argus-lens `/caption/batch`, its `training` caption with the trigger word first, written as `<image>.txt`), `train` (argus-forge `/config` then `/run`, only where forge's training is enabled; the LoRA is hashed and copied into the shared LoRA directory), `evaluate` (argus-proof `/run/stream` against the held-out references, then `/report/{run}`) and `pin` (the report re-read, the LoRA checked against `/report/{run}/manifest`, and a new **draft** identity version saved with `lora`, `proof_run` and `proof_export`). A step runs only when the one before it is done, never twice once done, and never beside another step of the same training; a failed step resumes (rendered candidates stay, a forge or proof run already started is followed). Every run of every step is recorded (inputs, the sibling's scan or run id, outputs, error) under `ARGUS_MINT_TRAINING_DIR`; a job a restart cut off reads as failed. `GET …/training` reports each step's status and the one step that may start next. Approving an identity with a `lora` is refused unless a passing training run pinned exactly it. `Identity` gains `proof_export` (pinned with `lora` and `proof_run`, all three or none), `check_metric` (`identity` or `likeness`), `min_score` and `training`, each left out of its hash while unset. Curator has no consistency measure without a face, so a `likeness` identity stops at `select`. New settings `ARGUS_MINT_CURATOR_URL`, `LENS_URL`, `FORGE_URL`, `PROOF_URL`, `TRAINING_DIR`, `TRAINING_EXPORTS_DIR` (the exports volume curator, forge and proof share) and `LORAS_DIR`; new capability `identity_training`. Thin clients in `training_clients.py`; the steps in `training.py`, behind `Protocol`s. [docs/projects.md](docs/projects.md#training-an-identity).
- **Posting, anchoring, and minting made optional (wire 1.13, #52, epic #47).** After both approvals a draft can be posted, published, both or neither.
  - **Posting.** `POST /drafts/{id}/posted {where, url, at, sha256}` records a post of an approved teaser's image, refused (409) when `sha256` isn't the draft's `image_sha256`, the draft isn't a teaser or isn't approved, or its image changed on disk. A draft can have several posts; the same post sent again is recorded once (200). Posts are kept beside the draft in `posts.json` and listed in `GET /drafts/{id}` (`posts`). Auth is a new scoped **poster token**, `ARGUS_MINT_POSTER_TOKEN` (argus-herald's), accepted by this route only; the moderator token works there too, and the server refuses to start when the two are equal. New capability `post`.
  - **The feed.** `GET /posts/ready` (open, paged, `?project=`) lists approved teaser drafts newest first, with the image URL and sha256, alt text, quote, attribution, label, `current` and the posts so far; a posted one stays listed, marked `posted`. argus-herald polls it; mint never pushes.
  - **Anchoring.** `argus-mint teasers anchor <project> --ledger --epoch [--tree]` anchors a Merkle root over the image sha256s of the project's posted teasers that no earlier anchor holds (each leaf's value is the PNG's sha256, OpenZeppelin `["bytes32"]` leaves), sharing `anchor`'s code: the epoch is checked first, the tree is written before sending, keys come from a keystore or the environment. The anchor (epoch, root, leaves, tx, tree path) is recorded under `ARGUS_MINT_ANCHORS_DIR/<project>/anchors.json`.
  - **Minting teasers.** `publish` (HTTP and CLI) takes an approved teaser too. Its metadata is a card's document with a `TeaserProvenance` (`kind: "teaser"`: each linked file's id, version and hash, the background's sha256, the frame, the unframed art, and the inpainting request for an embodied identity), described by its alt text, and its asset id is `keccak256(utf8("argus-mint/teaser/<project>/<T n>"))`. `metadata.content_hash()` stays the one hash. Card metadata, hashes and vouchers are byte-identical (`test_posting::test_card_metadata_is_byte_identical`).
  - **The tracker** fills `posted` (a draft of the teaser has a post) and `minted` (a draft of it is published).
  - **Export.** `argus-mint export <project> --out DIR` writes `T<n>.png` (the reviewed bytes) and `T<n>.json`: the linked files and hashes, background (with its seeds and checkpoint), frame, texts, seeds, checkpoint, LoRAs, inpainting input, reviews, posts, and each anchor with the image's Merkle proof.

- **Backgrounds and teaser drafts (wire 1.12, #49, epic #47).** A moderator-only job renders an approved scene's `backgrounds` through darkroom at `batch` priority: the scene's fixed prompt with the project's `style_lora` when it has one (recorded in each background's request; refused up front when darkroom's `/models` has no one-LoRA workflow for the checkpoint, `darkroom.check_render`), seeds derived from the project, scene and number, safety rejections retried with the next seed, every attempt recorded (`backgrounds.py`, `server_teasers.py`). They are stored under `ARGUS_MINT_BACKGROUNDS_DIR` (default `backgrounds`), one `manifest.json` per scene version, and the moderator approves or rejects each one, bound to its sha256. `POST /projects/{id}/teasers/{n}/draft` makes a teaser draft from the newest approved teaser links, refused unless the links, project, line, identity, scene, frame and chosen background are approved, every linked text has a fresh passing SingGuard verdict, no spoiler rule matches and the project has no problems. An embodied identity is inpainted into the scene's `character_area` through darkroom's image-to-image with a mask (`init_image.mask_base64`; its LoRA plus the project's style LoRA, at most two; `darkroom.check_inpaint` reads `/models` first); a viewpoint identity's teaser uses the background as is. Then the frame, the line's published text in `quote`, the attribution and the "generated image" label, baked to a PNG with critical chunks only (`teasers.bake_png`), byte-stable. `CardDraft` gains `kind` (`card`, the default, or `teaser`) and a `teaser` record (each linked file's id, version and hash, the background's id and sha256); `asset_id` and `consumer` become optional for teasers only, so card drafts, their hashes and provenance are unchanged. A teaser isn't edited or published as a card. `RenderRequest.init_image` records an inpainting input by sha256; `DarkroomClient.generate(req, init=...)` sends it and checks darkroom's record names the same input, mask and denoise. `render.render_requests` is the retry loop for any request builder. `GET /projects/{id}/tracker` reports each teaser's stages as mint works them out (`quote_final`, `concept_chosen`, `image_made`; `posted` and `minted` reserved, false) with its drafts' status and `awaiting`, so a UI never computes them. New capabilities `backgrounds` and `teasers`; `DraftSummary` gains `kind` and `teaser`. Example: a full-bleed teaser frame, `frames/example-teaser-v1` (`scripts/make_teaser_frame.py`), used by `projects/example-teasers`.

- **Teaser projects: files, checks and review (wire 1.11, #48, epic #47).** A project directory under `ARGUS_MINT_PROJECTS_DIR` holds `project.yaml`, `identities/`, `scenes/`, `lines/` (one quote per file, verbatim `text` plus `published`) and the teaser links, `teasers/<project>-v<n>.json` (`projects.py`, pure). Every file, the links included, is versioned and reviewed like a template (`catalogue.record_decision`, which now also approves JSON). `GET /projects`, `GET /projects/{id}` and `POST /projects/{id}/files/{kind}/{item}/{version}` (save a draft; approved and retired files never change) report cross-file problems, private spoiler-list hits (by rule number only, `ARGUS_MINT_SPOILERS`, `spoilers.py`) and SingGuard verdicts from darkroom's text pre-flight under the project's own `policy` (default `default`). The verdicts are stored in each file's `guard` block (field, text sha256, policy, outcome; not hashed, never taken from a client, `catalogue.record_guard`) and hold until the text or policy changes, so a restart keeps them. `POST /projects/{id}/files/…/review` refuses to approve while a spoiler rule matches or any text lacks a passing verdict (judging what's missing, with a darkroom), and teaser links until every line, identity and scene they name is approved. New capability `author_catalogue`. `DarkroomClient.check_text` takes a `policy`. Example: `projects/example-teasers` (neutral content). [docs/projects.md](docs/projects.md).

- **`requirements-test.txt`**: the test dependencies for a plain pip venv (`pip install -r requirements-test.txt && pytest`, no install of argus-mint needed: pytest gets `pythonpath = ["src"]`). ai-code-auditor's `validate_patch` builds its test environment from it, so fixes here are proven by pytest rather than lint only (cf. agent-composer#61). Pins match `uv.lock`; `tests/test_requirements_test.py` fails if they drift or a dependency is missing.
- **CLAUDE.md has a "Must never happen" table (#41).** Each row names the test or CI job that catches it, or says UNENFORCED with a follow-up issue (#53, hard rule 6, consumer-side). The prose that walked through modules is cut to the facts the code doesn't show (26 KB to 20 KB).
- New checks for rules that had none (`tests/test_must_never.py`): the pure core imports no network client (rule 8); no contract ABI has an ERC-20 surface, a payout-shaped function or a payable other than `Card.mint` (rule 5); no CLI option takes a key; OpenZeppelin's pinned commit and `evm_version = "cancun"` move together; compose publishes the Kubo RPC on 127.0.0.1 by default. CI's `verifier` job rebuilds `tests/fixtures/merkle.json` with `@openzeppelin/merkle-tree` and fails on any difference.

### Changed

- **A bio holds no numbers (hard rule 4).** A reply with a digit, in any script, is an unusable attempt and is retried, like one with stray braces. The name goes in after the check, so a name with digits is fine.
- argus-cortex is pinned `>=0.9,<0.10` (was `>=0.6,<0.7`), so the `server` extra has the suite's paved-road helpers (`fs`, `net`, `auth`, `limits`; ai-code-auditor#56).
- Id and value checks use `fullmatch` (argus-cortex's `fullmatch` codemod, ai-code-auditor#56), so they match the whole string: draft, sample-job and library entry ids, CIDs, template variable and frame slot names, and the SIWE domain, scheme, URI, resources, nonce and date-times. `$` also matches before a final newline, so a value followed by `\n` used to pass these checks.
- **`submit` needs `--card`** (or `$ARGUS_MINT_CARD`) and refuses a voucher whose EIP-712 domain names another contract: its pre-flight checks ran against the contract the voucher named, so a forged voucher could point them, and the payment, at any contract.
- **`publish --dry-run` signs with a throwaway key, never the real one** (and doesn't load it), so a dry run's voucher (local pins, maybe placeholder art) can't mint. `signer_is_ephemeral` is always true for a dry run.
- **Wire 1.10: slot texts are bounded.** `texts` in draft, edit, sample, preview and layout requests takes at most 16 slots, named like frame slots, each up to 2000 characters.
- `freeze --uri` takes only `ipfs://<cid>` or a bare CID, checked before connecting: a freeze can't be undone.
- Provenance `art` must be an `ipfs://` URI; a bare CID is refused. A render without variables leaves `variables` out of provenance, as with `loras`. Whole floats of 1e21 and more stay floats in hashed JSON, as JavaScript writes them.
- A frame's overlay and fonts must be paths inside its directory (relative, no `..`, no symlink out).
- A template can't offer a LoRA option it already applies in `loras`.
- `Library.thumbnail` serves widths 1 to 1024, rounded up to one of a few cached sizes.
- `ARGUS_MINT_*` settings that are set but empty take their defaults.
- `chain.connect`'s error names each RPC by scheme and host only: provider keys stay out of it.

### Fixed

- A teaser draft checks the spoiler list against its project's own frame again (its YAML's strings), as it does the linked texts, so a rule added after the frame was approved holds the teaser.
- `scripts/capture_frame.py` refuses to write a PNG that is the overlay of an approved or retired frame (a spec copied for a new version that still names the old PNG), and puts the PNG back whatever stops the capture.
- The identity check never raises on unreadable art or a proof answer whose `metrics` isn't an object: both are `error` records that hold the teaser.
- **The example's T1 figure fits the lamp room (#67).** `projects/example-teasers` painted the keeper as a head-and-shoulders portrait over the whole 448x704 centre of the lamp room, over the lamp on the sill. The lamp-room scene's `character_area` is now a standing figure's box left of centre, `{x: 96, y: 512, width: 288, height: 512}` (under half the old area, clear of the sill lamp, the wall picture and the wall lamp in each of the scene's three backgrounds, and running to the bottom edge, so the mask has no edge below the figure). The keeper's `prompt` asks for a three-quarter length figure standing in a dim room, seen from a few steps away and lit from one side by lamplight; its `negative` turns away close-ups and flat front lighting. Both files are drafts, so they are edited in place (the scene's background seeds are unchanged). darkroom thresholds the mask at 128 and pastes the result back through it, grown by 8 px, so a feathered mask edge from mint would be thrown away; no mask change here.
- `cards.write_atomic` writes a unique, fsynced temp file and removes it on failure; catalogue decisions validate the edit in a temp file and rename it over the original, so neither is left half-written.
- `bios.clean` never returns more than `max_chars`, and a bio's `max_chars` holds once the name is in.
- darkroom: a record without `guard.enforcing_policy` is an error, not a pass; a `complete` event without a record or with malformed data is an error result, not an exception; the text check turns a non-JSON or non-object answer into a `DarkroomError`; `final_prompt` matches darkroom 0.2's trigger-word rule (whole words, any case).
- `indexer.follow` pins the last block's hash before reading logs and checks it after, refuses logs from another branch, and skips `removed` logs.
- `argus-mint sample` keeps a render's art, seed and framed preview when its bio fails. `draft --library` refuses `--lora` cleanly (exit 2); `create_draft` refuses a library entry with a renderer with a `ValueError`.
- Every pin of a card is named by template, version and seed (the metadata pin was named by template only).
- Unreadable or oversized art is a `FrameError`, not a 500. Mixed-case blocklist terms match.
- `scripts/api_fixture.py` writes nothing unless its sample job finished `done`.
- verifier: a malformed drand beacon returns `{ok: false}`; `readRevealedSecret` honours `block` and skips removed logs.
- Tests that passed vacuously (no example frames, bios or demo mints found) or asserted too little (unsigned owner edits, a live publish without a signer, the CLI's `--text`/`--bio` checks) now check what they claim.

## [0.2.1] - 2026-11-14

### Added

- **Sampling per checkpoint (wire 1.8, #6).** A template's `sampling_by_model`, keyed by a checkpoint it lists, overrides the family's sampling. Flux schnell needs it: it shares darkroom's `flux` workflow with dev but takes about 4 steps, not 20. Like the per-family fields, it is left out of the template hash while empty, so existing templates keep their hash.
- **Templates are checked against darkroom's workflows (wire 1.7, #10).** `darkroom.check_template` reads darkroom's `GET /models` and reports anything that would make a render fail with a 400:
  - a checkpoint, LoRA, sampler or scheduler darkroom doesn't have
  - a checkpoint with no workflow for a LoRA count the template allows
  - a workflow given a negative prompt, `guidance` or `clip_skip` it has no slot for, or missing `guidance` it needs

  It runs in three places. `argus-mint preflight` runs it before the text check. The server serves it at `GET /templates/{id}/{version}/check`, with the `check_templates` capability. Approving a template through the API is refused (409) while it reports problems.
- **Darkroom's workflow is recorded with each attempt.** Each attempt keeps the workflow's name and sha256 (`attempts[].workflow`) in drafts, library entries and `publish` output.
- **Provenance records the render's choices (wire 1.6).** The metadata's `provenance`, which the voucher's `contentHash` covers, gains `variables`, `model` (the checkpoint) and `loras` (name and weight; a whole weight is written as an integer, so every JSON library hashes the same bytes). With the template hash and seed they rebuild the exact render request, so a card's art can be reproduced and checked from public data alone (hard rule 7). The variables come from the template's fixed lists, so no free text is added (hard rule 1). They are left out when unset: cards minted before this keep their `contentHash`, but don't say which variables, checkpoint or LoRAs made them. `Provenance.for_render` builds the block for both the CLI and the server.

- **The portrait library in the API fixture** (#14), for argus-assay's and argus-studio's demo mode. `fixtures/api/library.json` is `GET /library` for six whole groups of the pre-rendered library (every checkpoint each, ids and group numbers as in the full library), with a 640 px JPEG per entry in `fixtures/api/library/`. One recorded draft is made from a library entry.
- `scripts/api_fixture.py` takes its art and library subset from a built library (`--library`, `--groups`); `ART.png` arguments are optional. The fixture's copy of template v2 also offers LoRA options, for the picker.
- `tests/test_api_fixture.py` fails when the fixture is stale: wire version, response shapes, missing images, groups missing a checkpoint.

### Fixed

- **`check_template` checks a checkpoint darkroom lists without a family** against its path's family's workflows (as darkroom reads it). Before, only family-agnostic workflows matched, so a Flux workflow's missing slots went unreported.
- **`DarkroomClient.models()` waits at most 30 s**, not the 900 s a generation may take, so a stalled darkroom can't hold a template check, an approval or `preflight` for 15 minutes.
- `check_template` no longer passes every LoRA when darkroom lists no LoRA files (only a reply without a `loras` key goes unchecked), and a family-agnostic workflow listed before the family's own no longer hides that workflow's missing slots. A malformed `GET /models` reply raises `DarkroomError` instead of a 500.

They are now written as integers, like LoRA weights. Styles exist since 0.2.0; no card minted so far has one.

## [0.2.0] - 2026-11-09

### Changed (breaking)

- `argus-mint mint` is gone. A card is now `draft` → `review` (the moderator and the owner each approve the exact image) → `publish`, and nothing is pinned or signed before both approvals. Scripts that called `mint` need the three steps; `submit` takes `publish`'s output as it took `mint`'s.

### Added

- **Image review before publishing.** `argus-mint mint` is replaced by `draft` (render and frame into a local draft), `review` (the moderator and the owner each approve or reject the exact image, bound to its sha256) and `publish` (pin, metadata, signed voucher). `cards.check_publishable` refuses a draft that lacks either approval, was rejected, or whose files changed. Nothing reaches IPFS or a voucher before both approvals.
- **Frames.** `frames` module and `[frames]` extra (Pillow): a reviewed PNG overlay with an art window and an optional name slot, composited onto the render. Provenance gains optional `frame` (id, version, hash) and `art` (the unframed render's ipfs:// URI). Both are omitted when unset, so existing cards' `contentHash` is unchanged. `argus-mint frames` validates a directory of frames; there's a placeholder `frames/example-plain-v1`.
- **Card text and bios.** Frames have named text slots (`texts:`) with fonts, wrapping, shrink-to-fit and ellipsis clipping. `bios` module: a reviewed bio template prompts a language model (`ChatWriter`, OpenAI-style `/chat`; the example uses Mistral NeMo). The model sees only fixed-list values and a `{name}` token, and the real name goes in afterwards. darkroom's text pre-flight screens each bio (`DarkroomClient.check_text`), retrying flagged replies. `draft --bio --writer --text slot=value`. Provenance gains optional `bio` (template id, version, hash, model); the bio becomes the metadata `description`. The card-green frame ships with Cinzel and Crimson Text (SIL OFL).
- **`argus-mint sample`** renders a few combinations of a draft template (optionally framed) to local files for its reviewer, through `render.render_for_review`. It never pins, signs or mints.
- **`argus-mint serve`**: the card workflow over HTTP for argus-studio and argus-assay (`server` extra, port 8108). It lists templates, frames and bios; creates, lists and shows drafts and their images; takes reviews; and publishes. The moderator authenticates with a bearer token. The owner signs an EIP-4361 challenge naming the draft, the decision and the image hash, so neither can act as the other. It uses cortex's write guard and CORS, a read-only mode, and `/health` capabilities. The wire contract `schema/mint-wire.schema.json` comes from `argus-mint schema`, and demo-mode fixtures live in `fixtures/api/`. A Docker image (`ghcr.io/smk762/argus-mint`, published on tags) and a compose profile run it. The CLI and the server share `workflow.create_draft`/`publish`.
- **Catalogue review over HTTP (wire 1.1).**
  - **Samples:** `POST /samples` runs sample cards of a draft template, frame or bio template as a background job, with `GET /samples` to fetch them.
  - **Frame previews:** `POST /frames/{id}/{v}/preview` shows a frame on a draft's or sample's art.
  - **Decisions:** `POST /{templates,frames,bios}/{id}/{v}/review` approves or retires a file. `catalogue.record_decision` writes the decision into the YAML, keeping its comments, and restores the file if it no longer validates.
  - **Listings:** they gain `file` and, for templates, `combinations`; `/health` gains the `sample` and `review_catalogue` capabilities.
- **LoRA choices and sampling per checkpoint family (wire 1.5).**
  - **LoRAs:** templates offer `lora_options` (reviewed: allowed weights, trigger words, compatible checkpoints) and `max_loras`. Renders choose from them with `--lora NAME[@WEIGHT]` or `loras` on `POST /drafts` and `/samples`.
  - **Sampling per family:** `sampling_by_family` sets sampling per checkpoint family, and `Sampling.guidance` covers Flux.
  - **Negative per family:** `negative_by_family` sets the negative prompt per checkpoint family (`""` for Flux, which has no slot for one).
  - **Hashes:** templates that use none of this keep their hash.
  - **darkroom:** LoRAs and families other than SDXL need argus-darkroom 0.1.3 or later with a workflow directory (its Docker image's default), which picks a workflow per family and LoRA count.
- **Selectable checkpoints and a pre-rendered library (wire 1.4).**
  - **Checkpoints:** templates gain `models`, a reviewed list of checkpoints a card may use. Choose one with `draft --model`, `sample --model`, or `model` on `POST /drafts` and `/samples`.
  - **Building:** `argus-mint library build` renders diverse combinations on each checkpoint, with the same variables and seeds, safety-checked and resumable.
  - **Serving:** `/library` and `/library/{id}/image` serve the library, and `POST /drafts` with `library` (or `draft --library --entry`) makes cards from it without a GPU, if the approved template renders exactly that request.
  - **Template v2** lists the eight SDXL checkpoints.
- **Owner edits and styling (wire 1.3).**
  - **Endpoint:** `POST /drafts/{id}/edit` lets the card's owner change its name, bio, display text and style, by signing a challenge that covers exactly that change. The moderator only approves or rejects.
  - **Styles** (`metadata.CardStyle`): a border tint (`frames.tint_matrix`, the same numbers Pillow and an SVG `feColorMatrix` use), plus per-slot text colour, an effect (shadow, outline or glow) and a background box. Any colours; `style_locked` frames refuse them.
  - **Browser preview:** `POST /frames/{id}/{v}/layout` and `GET /frames/{id}/{v}/fonts/…` let a browser draw the card as SVG while it is styled. The baked PNG is what's reviewed.
  - **Provenance** gains optional `style`. Create, samples and frame previews accept a style too.
  - **Redraw:** the card is redrawn on the same art, and both approvals are needed again.
  - **History:** `CardDraft.edits` records each change, and `BioRecord.edited` marks a bio a person changed.
- **Auto-moderation** (`ARGUS_MINT_AUTO_MODERATE=1`): the platform gates on safety, the owner on quality.
  - **When it approves:** when darkroom's image and text checks passed and the name and display text pass the word filter, the moderator's approval is recorded automatically.
  - **When it holds:** otherwise the draft waits for a human moderator, with the reasons in `CardDraft.auto_check`.
  - **The word filter:** `moderation.WordFilter` is better-profanity (new in the `server` extra) plus `ARGUS_MINT_BLOCKLIST`.
- `templates/example-portrait-v2.yaml` (draft): clean full-bleed portraits for framing, without the card frames, lettering and badges v1's "card art" produced.
